# PROJECT_SCOPE.md —— 项目范围

## 首版包含什么

- 网页端（可被搜索引擎收录的公开内容页）＋ 微信小程序端，共用同一套 CloudBase 后端；
- 面向中国劳动争议场景的问答：基于审核过的法律法规、案例与公开问答材料；
- 检索：纯本地中文字符 n-gram/BM25 关键词检索（不使用向量数据库、不接入付费 embedding API）；
- 生成：DeepSeek 仅根据检索到的材料生成回答；
- 回答必须带可核验来源（source_id、标题、条款、官方 URL、效力状态），source_id 经过程序校验；
- 无有效依据时明确说明“当前资料不足，无法可靠判断”。

## 首版不包含什么

- 原生 App；
- 支付、文件上传；
- 复杂用户系统、登录注册体系；
- 运营管理后台；
- 向量数据库与付费 embedding API；
- 独立服务器与境外节点；
- 非授权内容（付费数据库、公众号全文、未授权专业手册）。

## 首版覆盖的六个问题场景

首版只覆盖以下六个具体产品场景：

1. 违法解除与经济补偿；
2. 拖欠工资；
3. 加班费；
4. 未签书面劳动合同；
5. 试用期争议；
6. 社会保险与竞业限制。

## 地域边界（第一版）

- 第一版知识资料只覆盖全国性法律、行政法规、司法解释和最高人民法院权威案例；
- 第一版不导入地方性法规、地方工资标准和地方仲裁口径；
- 用户问题依赖具体地区规则时，必须提示“当前版本尚未覆盖该地区规则”，不得用全国规则代替地方规则；
- 后续由项目经理明确选择首个地方版本。

## 回答结构（Phase 4/5 起）

回答由 DeepSeek 依据检索到的 `[S#]` 证据生成，结构清晰，至少包含：

1. 初步说明；
2. 相关依据（可带 `[S#]` 引用）；
3. 用户下一步可以做什么；
4. 信息边界（非律师意见、不预测胜诉率、不保证结果、地方政策与完整案情可能影响结论）。

以上由 `packages/shared` 定义并校验（`AnswerSchema`），两端渲染一致；同时作为 AI 生成内容的显著文字标识。

## 各端职责

- **网页端（apps/web）**：公开内容静态生成，支持 SEO；问答交互通过 API 调用后端；
- **小程序端（apps/miniprogram）**：问答交互与结果展示，通过 API 调用后端；
- **后端（functions/api）**：检索 → DeepSeek 生成 → source_id 校验 → 返回结构化回答；唯一持有 DeepSeek Key。

## 收录原则

- 公开内容（法律法规页面、案例摘要、常见问答等）可被搜索引擎收录；
- 私人问答（用户输入生成的结果）不参与 SEO，不被收录。
